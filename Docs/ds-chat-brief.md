# ТЗ: Финальная дизайн-система и правила UI — ux42studio

> Задача для отдельного чата по UI. Контекст там полнее, поэтому скопируй этот документ целиком как первое сообщение.

## 1. Цель
Составить финальный документ `Docs/design-system.md` — единый источник правды по UI проекта ux42studio: токены, компоненты, паттерны, правила, анти-паттерны. Документ должен быть достаточным, чтобы новый разработчик (или AI-агент) верстал новые страницы без обращения к существующему коду для «примеров стиля».

## 2. Входные материалы (пути в репо)
- `src/app/globals.css` — CSS-переменные, светлая/тёмная темы, seed-tint
- `src/lib/mainPageContent.ts` — типы `ThemeSettings`, `ButtonVariant`, структура контента главной
- `src/components/ui/` — текущая библиотека компонентов
- `src/components/` — прикладные компоненты страниц
- `src/app/(public)/page.tsx` + `src/app/(public)/portfolio/[slug]/` — публичные страницы
- `src/app/(console)/` — консоль пользователя (layout, загрузки, список работ, viewer)
- `Docs/ui-rules.md` — текущие правила UI (свести с новым документом, не дублировать)
- `Docs/privacyContent` / `src/lib/privacyContent.ts` — для раздела копирайтинга юридических страниц

## 3. Структура целевого документа
### 3.1 Принципы
3–5 верхнеуровневых принципов дизайна проекта (что для нас «хороший UI»).

### 3.2 Токены (обязательный полный список)
- **Цвета**: semantic palette (bg, surface, text, primary, secondary, danger, border, muted...), для light и dark темы отдельно; правила использования seed-tint и режимов `ThemeBackgroundMode` (`default | seed-tint | solid`)
- **Типографика**: шкала размеров, weight, line-height, letter-spacing для заголовков/текста/UI-элементов
- **Радиусы, тени, отступы**: полная шкала spacing, радиусов, elevation
- **Motion**: длительности и easing, правило `prefers-reduced-motion`
- **Z-index**: уровни слоёв (base / sticky / dropdown / modal / toast)
- Формат: каждый токен — имя переменной + значение + пример использования

### 3.3 Компоненты
Для каждого компонента из `src/components/ui/` (и новых, если появятся):
- назначение, варианты, размеры
- все состояния: default / hover / active / focus-visible / disabled / loading / error
- do / don't (1–2 коротких примера)
- правила доступности (aria, клавиатура)

### 3.4 Layout и сетки
- Breakpoints и поведение колонок
- Правила ширины контента (max-width для разных типов страниц)
- Отступы секций, правила для header/footer

### 3.5 Навигация и паттерны
- Хедер: режимы из `ThemeHeaderMode` (`default | transparent | solid`), когда какой
- Мобильное меню, футер, floating-элементы (в т.ч. судьба FAB-помощника — см. §5)
- Паттерны страниц: главная, портфолио-страница автора, консоль, загрузка работ, просмотрщик

### 3.6 Доступность (WCAG 2.1 AA)
- Контрастные минимумы по токенам
- Focus management, навигация клавиатурой
- Требования к alt-текстам, ошибкам форм, лоадерам

### 3.7 Копирайтинг и локализация
- Тон и голос (EN / RU / ES)
- Правила кнопок (инфинитив vs императив), форм, сообщений об ошибках
- Правила юридических страниц (privacy, aviso legal, cookies)

### 3.8 Анти-паттерны
Список «так нельзя»: магические значения вместо токенов, инлайн-стили, дублирующиеся компоненты, несанкционированные цвета и т.д.

## 4. Технические требования
- Токены — один источник правды в `globals.css` (+ маппинг в `mainPageContent.ts`), никаких значений-дубликатов
- Компоненты — только из `src/components/ui/`, прикладные собираются из них
- Tailwind utility-классы, без сторонних UI-библиотек
- Документ должен ссылаться на реальные файлы и реальные имена классов/переменных, а не на абстрактные примеры

## 5. Открытые вопросы (решить в рамках чата)
- **FAB-помощник**: сейчас не функционирует. Решить: (a) убрать до запуска, (b) оставить и привязать к реальному функционалу (FAQ-блок, контактная форма, интерактивный онбординг). Рекомендация: для беты — убрать или заменить на ссылку «Сообщить о проблеме» (открывает mailto/форму).
- **Локализация**: EN по умолчанию, RU и ES — когда и как (сейчас контент главной захардкожен в `mainPageContent.ts` — предложить структуру для i18n)
- **Тёмная тема**: в каких местах обязательна, в каких отключена

## 6. Процесс работы
1. Аудит текущего UI: пройтись по всем страницам, зафиксировать фактическое состояние (что уже есть, что расходится)
2. Свести `Docs/ui-rules.md` и фактический код — найти расхождения
3. Составить `Docs/design-system.md` по структуре выше
4. Отдельным блоком в конце — список расхождений «код vs документ» с приоритетом (критично / желательно / можно позже)

## 7. Критерии приёмки
- Документ покрывает все разделы §3 без «TODO»
- Все токены подтверждены реальными значениями из `globals.css`
- Нет противоречий с текущим кодом (или противоречия явно помечены как задача рефакторинга)
- Для каждого компонента есть минимум один пример кода
- Раздел про FAB и локализацию содержит конкретное решение, а не «на обсуждение»
