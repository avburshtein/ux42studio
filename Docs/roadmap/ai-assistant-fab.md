# Roadmap: виртуальный помощник (AI Assistant) на FAB

> Ответ на вопрос «что сделать, чтобы FAB-помощник заработал».
> Статус: **не реализовано, спроектировано ниже**. Решение на 2026-09-26:
> до реализации FAB честно переименован в «Contact us» (иконка `Mail`),
> потому что обещать несуществующую функциональность нельзя.

## 1. Что происходит сейчас

`src/components/FAB.tsx` рендерится на `/u/[slug]` (страница дизайнера)
при `mpc.cta.visible` и ведёт на якорь `#contact` — к секции `CtaSection`
с email/WhatsApp. Это быстрый доступ к контакту.

До 2026-09-26 кнопка называлась `aria-label="Help"` и несла иконку
`CircleHelp`, что читалось как «виртуальный помощник». Функции за этим
не было — кнопка просто скроллила к контакту. Расхождение между обещанием
и поведением устранено: теперь это `Mail` + `Contact us`.

## 2. Что нужно сделать, чтобы ассистент заработал

### Шаг 1. Продуктовое решение (зачем он вообще)

Без ответа на этот вопрос остальное — бессмысленная механика. Варианты:

| Вариант | Что отвечает | Стоимость | Риск |
| --- | --- | --- | --- |
| **A. Помощник по портфолио** | «Какие кейсы?», «Сколько лет опыта?», «Как связаться?» | Низкая: ответы из данных D1 | Низкий |
| **B. Квалификация лида** | «Нанимаю UX-дизайнера, что предложите?» | Средняя: нужен сценарий диалога | Средний |
| **C. Полноценный ИИ-ассистент студии** | Вопросы об услугах, ценах, процессах | Высокая: нужен LLM-бэкенд | Высокий |

**Рекомендация: вариант A.** Он не выдумывает факты (ответы собираются
из уже опубликованных данных профиля), не требует LLM для большинства
запросов, не создаёт юридических и репутационных рисков. Позже A/B можно
перевести на LLM, когда будет понятен реальный спрос.

### Шаг 2. Техническая реализация варианта A (без LLM)

Новая Server Action / route, который читает профиль из D1 и отвечает
по фиксированным интентам. Ключевое: **не отдавать произвольные данные**,
только заранее определённые поля.

```
src/lib/assistant.ts              # интенты + сборка ответа из профиля
src/app/api/assistant/route.ts    # POST { intent } -> { answer, sources[] }
src/components/AssistantPanel.tsx # UI (dialog на базе ui/Dialog.tsx)
```

| Интент | Источник данных | Ответ |
| --- | --- | --- |
| `who_is` | `profiles.fullName`, `headline`, `bio` | Кто это и чем занимается |
| `experience` | `profiles.bio`, проекты с годами | Опыт и релевантные кейсы |
| `work` | `projects` (published) + категории | Какие проекты опубликованы |
| `contact` | `mainPageContent.cta` | Как связаться (email/WhatsApp) |
| `process` | `mainPageContent.expertise.processSteps` | Как устроена работа |

Критично: каждый ответ сопровождается ссылкой на секцию страницы
(`/u/slug#work`, `/u/slug#contact`), чтобы пользователь мог проверить.


### Шаг 3. Вариант C — подключение LLM (когда понадобится)

Если нужен настоящий ИИ-ассистент, есть готовый путь — **репозиторий
ACOLDP** (`https://github.com/avburshtein/ACOLDP`): Cloudflare Worker
с интеграцией Gemini и уже перенесёнными UI-примитивами UX42.

```
FAB (u/[slug]) -> AssistantPanel (client)
                    -> POST /api/assistant (этот проект, Cloudflare Worker)
                        -> ACOLDP Worker (Gemini) или напрямую Gemini API
```

Почему через ACOLDP, а не напрямую:

1. Не дублировать ключ Gemini и логику фолбэча моделей
   (`gemini-2.5-flash → 2.5-flash-lite → 2.0-flash → 2.0-flash-lite`).
2. ACOLDP уже умеет отдавать JSON по схеме — можно попросить структурированный
   ответ `{ answer, sources[], relatedProjectSlugs[] }`.
3. UI-примитивы уже унифицированы между проектами.

Обязательные условия перед прод-подключением:

- [ ] Системный промпт ограничен доменом: «отвечай только о работах, услугах
      и контактах студии; если не знаешь — скажи и предложи написать напрямую».
- [ ] Тексты кейсов кладутся в контекст запроса, а не берутся из памяти модели,
      иначе неизбежны галлюцинации.
- [ ] Каждый ответ с цитатой на источник (`relatedProjectSlugs` → ссылки).
- [ ] Rate limit на `/api/assistant` (защита от расхода квоты и от флуда).
- [ ] Таймаут и фолбэк: при ошибке Gemini показать контакты, а не «упавшего бота».
- [ ] Ключ Gemini — только в Cloudflare Secrets, **никогда** в клиентском бандле.
- [ ] Не отправлять в модель персональные данные посетителей (см. §4).

### Шаг 4. Правки в UI

- FAB меняется обратно: иконка `MessageCircle`/`Sparkles`,
  `aria-label="Ask about this portfolio"`.
- Панель: `ui/Dialog.tsx` (уже есть, Radix — фокус-ловушка и Esc из коробки).
- Обязательно `aria-live="polite"` на область ответа, чтобы скринридер
  озвучивал реплики ассистента.
- Клавиатура: открытие по `Enter`/`Space`, закрытие по `Esc`, возврат фокуса
  на FAB после закрытия (Radix делает это сам).

### Шаг 5. Что учесть в дизайн-системе

В `Docs/ui/Main_page_Spec.md` §11 (FAB) сейчас зафиксировано назначение
«якорь на #contact». При переходе на ассистента спеку нужно обновить:
иконка, `aria-label`, поведение, и добавить `AssistantPanel` в реестр
компонентов (`Docs/design-system.md` §3 — сейчас там реестр `ui/*` и прикладных
компонентов, §9 — список открытых расхождений).

## 3. Проверка готовности (Definition of Done)

- [ ] Ассистент отвечает на 5 интентов из §2, ответы содержат ссылки на секции
- [ ] Полностью работает с клавиатуры, фокус не теряется (WCAG 2.1 AA)
- [ ] `aria-live` озвучивает ответы
- [ ] Пустой/ошибочный ответ не ломает вёрстку (зарезервирован min-height)
- [ ] Работает в светлой и тёмной темах, только токены M3
- [ ] `prefers-reduced-motion` отключает анимации появления
- [ ] Мобильный: панель не перекрывает FAB, закрывается кнопкой
- [ ] При недоступности LLM показываются контакты, а не ошибка
- [ ] Privacy Policy §6 обновлён (см. §4)

## 4. Юридический аспект (обязательно)

Если в ассистент попадают сообщения пользователей, они являются
персональными данными. Тогда:

- **Privacy Policy §6 (Destinatarios)**: добавить Google LLC (Gemini)
  как процессора, если используется вариант C. Для варианта A правки не нужны —
  данные не покидают инфраструктуру Cloudflare.
- **Раздел «Cookies»**: баннер не нужен, если ассистент не ставит идентификаторы
  сессии. Но история диалога в `localStorage` — это уже данные.
  Решение: **не хранить историю** (только текущий диалог в памяти компонента).
- Если история всё же нужна — срок хранения и право на удаление через
  privacy@ux42.studio.
