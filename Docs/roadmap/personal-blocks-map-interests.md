# Roadmap: персональные блоки на странице дизайнера — «Интересы» и «Карта»

> Идея из внешнего ревью копии страницы (референс — резюме-«one page»:
> блок MY SPECIALTIES с кольцевыми диаграммами, MY TRAVELS с картой мира,
> MY INTERESTS с иконками).
> Статус: **не реализовано, зафиксировано ниже** (2026-11-02).
> Решение на 2026-11-02: идеи понравились, но часть стоит дорого —
> берём по частям, сначала дешёвое и универсальное.

## 1. Что уже есть на странице дизайнера

Секции главной (`/u/[slug]`) живут в JSON-колонке `profiles.main_page_content`,
тип `MainPageContent` (`src/lib/mainPageContent.ts`), редактор —
`src/components/admin/MainPageContentEditor.tsx`.

| Секция | Что уже покрывает «референсные» блоки |
| --- | --- |
| `hero` | Заголовок, подзаголовок, до 3 CTA, полоса фактов (`hero.facts`) |
| `portfolio` | Карточки кейсов + бейджи статуса |
| `about` | До 5 абзацев + изображение |
| `experience` | Компания / роль / период / описание, порядок — drag-and-drop |
| `education` | Учреждение / степень / период / локация |
| `expertise` | Чипы навыков (`skills`), группы инструментов (`toolGroups`), строка «Project stack» (`stackNote`), этапы процесса (`processSteps`) |
| `cta` | Заголовок, описания, email/WhatsApp |

**Вывод:** навыки и инструменты уже показаны — дублировать их кольцевой
диаграммой не нужно. Не хватает двух вещей: **хобби/увлечений** (личность)
и **географии** (где была / где работала).

## 2. Идея A — блок «Интересы» ⭐ рекомендуется первым

Секция «MY INTERESTS» из референса: круглые иконки с подписями
(Music, Plants, Cooking…). Смысл — показать человека, а не только навыки.

### Варианты

| Вариант | Что это | Стоимость | Риск |
| --- | --- | --- | --- |
| **A1. Чипы с иконками** | Как Skills, но с иконкой и подписью | Низкая: расширить `expertise` новым массивом + иконка из набора lucide | Низкий |
| **A2. Круглые плитки** | Как в референсе: круг + подпись, сетка 3–4 в ряд | Средняя: свой компонент + сетка | Низкий |
| **A3. Донат-диаграмма скилов** | Кольцо «skill 0–100» из референса | Средняя: SVG-анимация + шкала 0–100 | Средний: данные об уровнях придуманы |

**Рекомендация: A2.** Чипы (A1) сливаются с секцией Skills визуально и
теряются; A3 требует честных числовых оценок навыков — на платформе для
чужих дизайнеров это превращается в выдуманные числа.

### Технические заметки

- Данные: `expertise.interests: Array<{ label: string; icon: string }>`
  в том же JSON — **миграция БД не нужна**, только тип + `normalizeMainPageContent`
  (fallback для старых записей → пустой массив).
- Иконки: `lucide-react` (уже в проекте) — значение `icon` хранится как
  строка-ключ, маппится на компонент в рендере; **безопасность**:
  никакого `dangerouslySetInnerHTML`, только белый список ключей.
- Админка: ряд редакторов в стиле существующего `TagList` (добавить/удалить
  иконку + подпись) + выпадающий список доступных иконок.
- Рендер: `src/components/portfolio/InterestsSection.tsx`, сетка
  `grid-cols-3 md:grid-cols-4`, круг `aspect-square` + подпись под ним.
- Доступность: иконка декоративная (`aria-hidden`), текст — реальная
  подпись; контраст подписи ≥ 4.5:1.

### Definition of Done

- [ ] Секция включается/выключается в админке, порядок — рядом с Skills
- [ ] Пустой список → секция не рендерится (как Experience/Education)
- [ ] Тёмная и светлая темы, только токены M3
- [ ] Иконка подписи читается скринридером
## 3. Идея B — блок «Карта» (MY TRAVELS)

### Сначала — развилка по смыслу

| Вариант | Что показывает | Смысл для рекрутера |
| --- | --- | --- |
| **B1. География биографии** | Города, где жила/работала (из `experience.location`) | «Где я была», личность |
| **B2. География кейсов** | Страны клиентов по кейсам | «Где применяла опыт» |
| **B3. Обе карты** | B1 + B2 разными цветами | Полная картина |

**Рекомендация: B1**, и только если у дизайнера реально накопится
география. B2 зависит от того, что в кейсах вообще есть страна клиента
(сейчас такого поля нет — это отдельная работа), B3 — дороже всех.

### Технические заметки

- Нужна сущность «страна/город» — на сейчас её нет ни в `profiles`, ни в
  `projects`. Значит: либо новая колонка/таблица (миграция), либо разбор
  строки `experience.location` по справочнику (хуже: нельзя выбрать).
- Карта мира — это SVG. Варианты: инлайн-SVG с контурами стран
  (вес ~50–100 КБ, но полный контроль и офлайн-работа) или
  внешняя библиотека/сервис (сеть, вес, лицензия).
- Тема: карта должна краситься токенами M3 (силуэт стран — `surface-variant`,
  выбранные — `primary`), т.е. **не картинка**, а вектор с `currentColor`.
- Вес и производительность: карта на мобильном — это ~100 КБ SVG;
  рисовать только при видимости (`IntersectionObserver`), иначе — статичная
  заглушка со списком стран.
- Доступность: карта декоративна (`aria-hidden`), рядом обязателен
  текстовый список стран — иначе блок недоступен с клавиатуры и для
  скринридеров.

### Почему дороже «Интересов»

1. Новая сущность данных (страна/город) + миграция + редактор выбора.
2. SVG-карта мира в вёрстке: поддержка токенов темы, адаптив, вес.
3. Список стран как доступная альтернатива (не «декорация без смысла»).
4. Нужно решить, что карта значит (B1/B2/B3) — иначе это просто «вау-картинка».

## 4. Порядок реализации (предложение)

1. **A2 «Интересы»** — дёшево, даёт эффект личности, универсально для
   всех дизайнеров платформы.
2. Пересмотреть через 1–2 месяца: нужны ли хобби вообще (по обратной
   связи от посетителей).
3. **B1 «Карта»** — отдельной задачей, когда будет понятен смысл и
   накопятся данные. Проверить, не покрывает ли уже потребность
   блок Experience с колонкой «локация».

## 5. Что НЕ делаем

- Прямой аналог референса (по копирайту «MY SPECIALTICS» и т.п.) —
  у платформы своя система секций, чужие названия будут выглядеть
  чужеродно. Референс — источник идеи, а не макета.
- Донат-диаграммы уровня навыков (0–100) — это выдуманные числа,
  на чужих профилях платформы они превратятся в «дизайнер с навыком 47».
- Блок «MY STORY» с таймлайном (референс) — у нас уже есть `experience`
  и `education` с периодами; дубль.
