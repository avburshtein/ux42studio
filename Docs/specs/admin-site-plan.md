# План доработок: `/admin/site` (тема, layout, сортировка кейсов, SEO)

> Статус: **вне текущего скопа** — отдельный этап после запуска MVP
> Зависимости: Этап 7 (блокеры публикации), Этап 8 (неполнота), Этап 9 (безопасность/UX), Этап 10 (archived)
> Ожидаемый результат: дизайнер может настраивать внешний вид своего публичного портфолио, порядок кейсов и SEO-метаданные

---

## Контекст

Сейчас `/admin/site` не существует — нет ни страницы, ни таблиц в БД. Публичное портфолио дизайнера рендерится по жёстко заданному layout'у, проекты сортируются только по `publishedAt`/`createdAt`, SEO-полей (meta title/description, OG-изображение) нет.

Этот документ описывает, что потребуется для появления `/admin/site`, но **не входит в текущий этап** и должен реализовываться отдельно.

---

## 1. Цели и границы

### Цели

1. Дать дизайнеру управлять внешним видом своего публичного портфолио.
2. Дать возможность задавать порядок отображения кейсов.
3. Дать возможность задавать SEO-метаданные (title, description, OG-изображение).

### Границы (что НЕ входит)

- Глобальные настройки всей платформы (это суперадминка).
- Кастомизация публичной главной `/` (это каталог платформы, не портфолио конкретного дизайнера).
- Смена шрифтов/цветов на уровне бренда (это глобальная дизайн-система).

---

## 2. Что настраивается

### 2.1 Тема портфолио

- Выбор цветового акцента портфолио (в рамках MD3-токенов).
- Выбор шрифтовой пары (заголовки/текст) из ограниченного набора.
- Тёмная/светлая тема по умолчанию.

### 2.2 Layout

- Порядок секций кейса (Intro → Problem → Research → Design → Testing → Showcase → Reflection).
- Видимость отдельных секций (скрыть/показать).
- Вариант шапки профиля (компактная/расширенная).

### 2.3 Сортировка кейсов

- Ручной порядок (drag-n-drop).
- Автоматическая сортировка (по дате публикации, по просмотрам).

### 2.4 SEO

- Meta title и description для профиля.
- OG-изображение (обложка профиля).
- Canonical URL.

## 3. Схема БД (новые таблицы)

Потребуются новые таблицы (в текущей схеме их нет):

### `portfolio_settings`

| Поле             | Тип     | Описание                           |
| ---------------- | ------- | ---------------------------------- |
| `id`             | text PK |                                    |
| `profileId`      | text FK | → `profiles.id` (unique)           |
| `themeAccent`    | text    | slug цветового акцента             |
| `headingFont`    | text    | шрифт заголовков                   |
| `bodyFont`       | text    | шрифт текста                       |
| `defaultTheme`   | text    | `light` / `dark` / `system`        |
| `headerVariant`  | text    | `compact` / `expanded`             |
| `sectionsOrder`  | text    | JSON-массив порядка секций         |
| `hiddenSections` | text    | JSON-массив скрытых секций         |
| `projectsSort`   | text    | `manual` / `publishedAt` / `views` |
| `seoTitle`       | text    |                                    |
| `seoDescription` | text    |                                    |
| `ogImageFileId`  | text FK | → `files.id`                       |
| `createdAt`      | integer |                                    |
| `updatedAt`      | integer |                                    |

### `project_manual_order`

Для ручной сортировки кейсов:

| Поле        | Тип     | Описание        |
| ----------- | ------- | --------------- |
| `profileId` | text FK | → `profiles.id` |
| `projectId` | text FK | → `projects.id` |
| `order`     | integer | позиция         |

PK по паре `(profileId, projectId)`.

## 4. Роуты и Server Actions

### Роуты

- `GET /admin/site` — страница настроек портфолио.
- (опционально) `GET /admin/site/sections` — отдельная вкладка для порядка секций.

### Server Actions (в `src/lib/actions/site.ts`)

| Action                | Назначение                           |
| --------------------- | ------------------------------------ |
| `updateSiteSettings`  | Сохранить тему/layout/SEO            |
| `updateSectionsOrder` | Сохранить порядок и видимость секций |
| `updateProjectsOrder` | Сохранить ручной порядок кейсов      |

---

## 5. Публичная часть

### Что изменится

1. **Профиль `/u/[slug]`** — читать `portfolio_settings` и применять тему/layout/сортировку.
2. **Страница проекта `/u/[slug]/[projectSlug]`** — читать порядок секций и скрытые секции.
3. **SEO** — генерировать `metadata` из `portfolio_settings` (title/description/OG).
