# Отправка писем (инвайты и подтверждение регистрации)

Письма отправляет модуль `src/lib/email/`:

| Файл | Назначение |
| --- | --- |
| `templates.ts` | Шаблоны писем (HTML + plain text). Создание инвайта + «аккаунт создан». |
| `send.ts` | Отправка: выбор транспорта, обработка ошибок, ссылки для писем. |

Транспорт выбирается автоматически, в таком порядке:

1. **Cloudflare Email Service** — биндинг `send_email` (имя `EMAIL`).
2. **Resend** — HTTP API, если задан секрет `RESEND_API_KEY`.
3. Иначе письма не отправляются, инвайт всё равно создаётся, а интерфейс
   показывает статус «Отправка писем не настроена» и сам код (его можно
   скопировать и отправить вручную).

Ошибка отправки **никогда** не отменяет создание инвайта и не ломает
регистрацию: `send.ts` не бросает исключений, а возвращает статус
(`sent` / `not_configured` / `failed`), который показывается в UI.

## Вариант 1 — Resend (рекомендуется: работает на Free)

1. Аккаунт на [resend.com](https://resend.com), домен `ux42.studio`
   добавить в **Domains** и подтвердить DNS-записи.
2. Создать API-ключ (API Keys → Create API Key).
3. Положить ключ в секреты:

   ```bash
   npx wrangler secret put RESEND_API_KEY
   ```

Бесплатный лимит — 3 000 писем в месяц. Для этого проекта (инвайты)
это с большим запасом.

## Вариант 2 — Cloudflare Email Service (нужен Workers Paid)

Email Sending доступен **только на тарифе Workers Paid**
(3 000 писем/мес включено, далее $0.35 за 1 000). На Free-плане
включить его нельзя.

```bash
# 1. Включить отправку для домена (один раз)
npx wrangler email sending enable ux42.studio

# 2. Раскомментировать биндинг в wrangler.toml:
#    [[send_email]]
#    name = "EMAIL"

# 3. Задеплоить
npm run deploy
```

## Переменные окружения

| Переменная | Где | Назначение |
| --- | --- | --- |
| `EMAIL_FROM` | `[vars]` в `wrangler.toml` | Адрес отправителя, можно `Имя <адрес>`. |
| `EMAIL_FROM_NAME` | `[vars]` | Имя отправителя, если не задано в `EMAIL_FROM`. |
| `APP_URL` | `[vars]` | Публичный адрес сайта для ссылок в письмах. Фолбэк — хост запроса. |
| `RESEND_API_KEY` | secret | Ключ Resend. |

## Что отправляется

1. **Письмо-приглашение** — при создании инвайта с email
   (`createInvite` → `sendInviteEmail`). Содержит код, кнопку
   «Открыть страницу регистрации» со ссылкой
   `/register?invite=CODE` (код подставляется в форму автоматически),
   5 пронумерованных шагов, блок «Если что-то пошло не так» и
   инструкции «что делать после регистрации».
2. **Письмо «аккаунт создан»** — после успешной регистрации
   (`/api/auth/register` → `sendRegisteredEmail`): подтверждение и
   план «сменить пароль → заполнить профиль → собрать первый кейс».
   Пароль в письмо **не** попадает намеренно — он показывается на
   экране один раз.

Шаблоны лежат в `src/lib/email/templates.ts`. Вёрстка писем — табличная
с inline-стилями: почтовые клиенты не поддерживают CSS-классы, это
исключение из правила «без инлайнов» для UI приложения.

## Проверка

Письмо уходит только на реальный адрес (тестовые `example.com` Gmail
отклоняет). Быстрый способ убедиться, что отправка настроена:

1. Суперадмин → `/super-admin/invites`.
2. Указать свой email → «Создать инвайт».
3. Под формой появится статус: «Письмо отправлено» / «не удалось» /
   «отправка не настроена».
